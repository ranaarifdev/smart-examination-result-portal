Abstract
--------------------------------------------------------------------------------
Traditional educational grading systems are plagued by slow feedback cycles, human calculation errors, and administrative bottlenecks. To address these challenges, we introduce the "Smart Examination Result Portal" for the Faculty of Computing and Emerging Technology (FCET). This system is a secure, full-stack web application designed to digitize the entire academic evaluation lifecycle. By introducing three distinct, role-based modules—Students, Teachers, and Administrators—the portal streamlines operations from mark submission to official result cards. 

The proposed solution utilizes lightweight, high-performance technologies, including Node.js and Express.js for application logic, and SQLite3 as a serverless relational database to store academic records. Key security features include 256-bit JSON Web Token (JWT) session authorization, bcryptjs password hashing, and real-time CAPTCHA protection for result queries. 

Expected results include a 70% reduction in administrative grading overhead, instantaneous student result checking, and 100% mathematical accuracy in GPA/CGPA calculations. Ultimately, this system establishes a reliable, premium digital infrastructure that empowers students and staff with transparent, secure academic data.

1. Introduction / Background
--------------------------------------------------------------------------------
Examination management is a core pillar of academic institutions. At the Faculty of Computing and Emerging Technology (FCET), consolidating semester results, verifying grades, and releasing official result cards has traditionally relied on fragmented spreadsheets and manual record-keeping. The lack of a centralized dashboard leads to significant delays in publishing results and places a massive logistical strain on administrators.

Developing a specialized examination portal addresses these limitations. It bridges the communication gap between students, faculty members, and administrators, providing instant grade access and reducing administrative friction.

### Sustainable Development Goals (SDG) Alignment:
The Smart Examination Result Portal actively aligns with the following United Nations Sustainable Development Goals (UN SDGs):
* **SDG 4: Quality Education** 
  By providing immediate, secure, and detailed access to subject-wise grades, GPAs, and CGPA trends, the portal promotes transparency. It enables students to monitor their performance, identify learning gaps, and receive feedback, which enhances overall educational outcomes.
* **SDG 9: Industry, Innovation, and Infrastructure** 
  Replacing manual paper-based grading with a secure digital database and responsive web workflows promotes innovation. It provides the institution with resilient digital infrastructure, laying a path for modern campus automation.

3. Project Objectives
--------------------------------------------------------------------------------
The project objectives are designed to be Specific, Measurable, Achievable, Relevant, and Time-bound (SMART).

* **Main Goal:** 
  To design, implement, test, and deploy a secure, high-performance, and responsive full-stack Smart Examination Result Portal for FCET to completely digitize student and grading records.

* **Specific Objectives:**
  1. **Design** a premium, institutional Navy & Red responsive user interface (UI) featuring unified style rules for consistent aesthetics across desktop and mobile screens by Week 3.
  2. **Implement** robust user authentication and session security utilizing 256-bit JWT and salted bcryptjs password hashing by Week 5.
  3. **Build** a lightweight, relational SQLite3 database schema consisting of users, students, teachers, classes, exams, results, and notification tables by Week 6.
  4. **Develop** rest APIs to handle student results lookup, automatic GPA/CGPA calculations, and system stats for the Admin dashboard by Week 7.
  5. **Evaluate** the system by executing verification tests to guarantee under-1-second page loads and 100% arithmetic accuracy in grading totals by Week 8.

4. Scope of the Project
--------------------------------------------------------------------------------
The Smart Examination Result Portal covers the digital examination process for the Faculty of Computing and Emerging Technology (FCET).

### What the Project Covers:
* Role-based Student, Teacher, and Administrator dashboards.
* Real-time public result checking with CAPTCHA validation.
* Auto-calculation of student GPAs, CGPAs, and subject-wise percentages.
* Class lists, student enrollment counts, and marks entry systems for teachers.
* Student and teacher user account registration, password hashing, and authorization.
* A campus notice marquee and dynamic portal announcements.
* Print-ready official result cards with dynamic QR verification codes.

### What the Project Does NOT Cover:
* An online financial transaction gateway (fees are tracked as paid/pending statuses but payments are handled offline).
* Live virtual classroom hosting or online video lectures.
* Real-time automated attendance tracking (attendance values are entered manually).

### Boundaries & Intended Users:
The portal is strictly bounded within the FCET network. The intended users include:
1. **Students:** View academic progress, search results, and download PDFs.
2. **Teachers:** View assigned classes and input student course grades.
3. **Administrators:** Oversee registrations, edit users, and publish grades.

6. Feasibility Study
--------------------------------------------------------------------------------
Before system implementation, a multi-dimensional feasibility study was performed.

* **Technical Feasibility:** Highly Feasible. 
  The project utilizes standard web technologies (HTML, Custom CSS, Vanilla JavaScript, Node.js, Express.js). SQLite3 is a lightweight, reliable, file-based database that requires no complex hosting configurations, making it extremely practical for a local deployment.
* **Economic Feasibility:** Feasible. 
  Development costs are close to zero as it utilizes open-source technologies (VS Code, Node, npm, SQLite3, Phosphor Icons). Host system resource requirements are minimal, allowing it to run smoothly on standard local computers.
* **Operational Feasibility:** Highly Feasible. 
  The system operates through standard web browsers, meaning no special client-side installation is needed. It matches existing educational evaluation workflows, resulting in a minimal learning curve for faculty and students.
* **Schedule Feasibility:** Feasible. 
  The project was planned as an 8-week SDLC project. Core backend APIs, secure JWT setups, database seeding, and the premium responsive UI are already completed and verified.

7. Methodology / System Design
--------------------------------------------------------------------------------
The portal is built utilizing the **Agile Scrum Methodology**, allowing for rapid, iterative sprint cycles that quickly transform design mockups into functional features.

### System Design Approach:
The application adopts a **3-Tier Model-View-Controller (MVC)** software architecture:
1. **Presentation Layer (View):** Premium, responsive frontend built with HTML5, Custom HSL Vanilla CSS, Phosphor Icons, and Google Fonts.
2. **Application Logic Layer (Controller):** Node.js and Express.js servers hosting secure RESTful APIs and JWT verification middleware.
3. **Data Layer (Model):** SQLite3 database storing persistent relational tables.

  +-------------------------------------------------------------------+

  |  (Login / Register)       (Public CAPTCHA)      (Role-Based)      |
  |       |                        |                      |           |
  |       v                        v                      v           |
  |  [Users Table]           [Students Table]       [Results Table]   |
  |  [Students/Teachers]     [Results Table]        [Classes Table]   |
  |                          [Exams Table]          [Notifications]   |
  |                                                                   |
  |  P4: Admin Management    P5: Marks Entry                          |
  |  (Stats / Publishing)    (Teacher Grading)                        |
  |       |                        |                                  |
  |       v                        v                                  |
  |  [All Tables]            [Results Table]                          |
  |  [Notifications]         [Classes Table]                          |
  +-------------------------------------------------------------------+

#### Authentication Flow:

  [User] --> [Enter ID + Password + Role]
    --> [POST /api/auth/login]
    --> [Server: Query users + students/teachers JOIN]
    --> [bcrypt.compare(password, hash)]
    --> [Valid? -> jwt.sign(payload, secret, {expiresIn: 24h})]
    --> [Set Cookie + Return Token]
    --> [Redirect to Dashboard]

#### Public Result Search Flow:

  [Guest] --> [Enter Roll No + Program + CAPTCHA]
    --> [Validate CAPTCHA Code]
    --> [GET /api/public/search?roll_number=XXX]
    --> [Server: Query students JOIN users]
    --> [Found? -> Return name, program, semester, CGPA]
    --> [Render Official Result Card + QR Code]
    --> [Print / Download PDF]

#### Admin Publishing Flow:

  [Admin] --> [Login -> JWT Verified]
    --> [GET /api/admin/stats -> View Pending Count]
    --> [Click "Publish Results"]
    --> [UPDATE results SET status='published' WHERE exam_id=?]
    --> [POST notification -> "Results Published"]
    --> [Students Can Now View on Dashboard]
